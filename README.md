# ЦАИУ — Telegram-бот приёмной комиссии

Бот отвечает на вопросы абитуриентов на **русском, казахском и английском** языках.
Ищет ответы на сайте университета через систему умного поиска и формулирует ответы через ChatGPT.

## Как это работает — простыми словами

### Обычный ChatGPT: проблема

Если просто написать в ChatGPT "Сколько стоит обучение в ЦАИУ?", он не знает правильного ответа — его данные устарели, и он не имеет доступа к сайту вашего университета. Он может придумать ответ или сказать что не знает.

### RAG — умный поиск + ChatGPT

**RAG** (Retrieval-Augmented Generation, в переводе: "генерация с поиском") — это подход, при котором перед ответом система сначала **находит нужную информацию** в вашей базе данных, и только потом ChatGPT формулирует ответ **на основе найденного**.

Это как если бы ChatGPT мог прочитать нужную страницу вашего сайта прямо перед ответом.

### Как работает бот шаг за шагом

```
Абитуриент пишет вопрос в Telegram:
"Какие документы нужны для поступления?"
        ↓
1. ПЕРЕВОД
   Если вопрос на казахском или английском — переводится на русский
   (поиск по базе работает на русском языке)
        ↓
2. УМНЫЙ ПОИСК в базе знаний
   Система ищет похожие фрагменты из сайта caiu.edu.kz
   Находит: "[Правила приёма > Необходимые документы]
             Аттестат, удостоверение личности, фотографии..."
        ↓
3. ГЕНЕРАЦИЯ ОТВЕТА
   ChatGPT читает найденные фрагменты и формулирует ответ
   на языке абитуриента (русский / казахский / английский)
        ↓
4. Абитуриент получает ответ от имени "Айданы"
```

### Что такое "база знаний" и "индексация"

**База знаний** — это векторная база данных Qdrant. В ней хранятся все страницы сайта университета в специальном формате.

**Индексация** — это процесс наполнения базы знаний. Система:
- Скачивает все страницы с caiu.edu.kz (по sitemap)
- Разбивает каждую страницу на **фрагменты** (чанки) по ~200 слов
- Для каждого фрагмента сохраняет контекст: из какой страницы, из какого раздела
- Для каждого фрагмента GPT генерирует 4 возможных вопроса — чтобы поиск работал лучше
- Все это сохраняется в базу

**Почему фрагменты, а не целые страницы?** Потому что ChatGPT не может получить всю страницу целиком (слишком много текста). Да и искать нужно конкретный абзац, а не всю страницу "Об университете".

### Что такое "векторный поиск"

Обычный поиск ищет точное совпадение слов. Если абитуриент напишет "бумаги для поступления" вместо "документы для приёма" — обычный поиск ничего не найдет.

Векторный поиск работает иначе: каждый фрагмент текста преобразуется в набор из 1536 чисел (вектор), который описывает **смысл** текста. Похожие по смыслу фрагменты получают похожие векторы. Поэтому "бумаги для поступления" и "документы для приёма" найдут один и тот же фрагмент.

### Горячая переиндексация (Hot-Swap)

Когда на сайте обновляется информация, нужно обновить базу знаний. Проблема: индексация занимает **30–60 минут**. Останавливать бота на это время нельзя — абитуриенты продолжают писать.

Решение: **Blue/Green деплой**. В базе данных всегда существуют две копии данных — "синяя" (`_blue`) и "зелёная" (`_green`). Одна активна (бот работает через неё), другая — в резерве.

При переиндексации:
1. Система пишет новые данные в **резервную** копию — бот всё это время работает со **старой**
2. Когда новые данные готовы — система мгновенно переключает бота на новую копию (атомарный своп алиаса)
3. Старая копия удаляется

Для бота и абитуриентов всё это незаметно — ни одного прерывания.

## Структура проекта

```
rag system/
│
├── bot/
│   └── run.py              ← Весь Telegram-бот (один файл)
│                             Обрабатывает сообщения, переводит,
│                             запрашивает поиск, отвечает через GPT
│
├── rag_service/            ← Сервис поиска (FastAPI, порт 8001)
│   ├── run_api.py          ← Точка входа: запускает сервер
│   ├── docker-compose.yml  ← Запуск базы данных Qdrant
│   ├── .env                ← Ключи и настройки (не в git!)
│   ├── hot_swap_state.json ← Какая коллекция сейчас активна (создаётся автоматически)
│   ├── schedule_state.json ← Расписание переиндексации (создаётся при планировании)
│   └── app/
│       ├── config.py       ← Все настройки системы
│       ├── main.py         ← API эндпоинты (/search, /index, /health...)
│       ├── parser/         ← Скачивание и обработка страниц
│       │   ├── crawler.py          ← Получает список URL из sitemap
│       │   ├── extractor.py        ← HTML → чистый текст с ## заголовками
│       │   ├── chunker.py          ← Текст → фрагменты по ~200 слов
│       │   └── google_docs_reader.py ← Чтение Google Docs (с определением заголовков)
│       ├── indexer/        ← Сохранение в базу данных
│       │   ├── embeddings.py       ← Преобразует текст в векторы (OpenAI API)
│       │   ├── storage.py          ← CRUD операции с Qdrant
│       │   ├── question_generator.py ← GPT генерирует вопросы к каждому фрагменту
│       │   ├── catalog_builder.py  ← Синтетические фрагменты о факультетах
│       │   ├── pipeline.py         ← Единый процесс индексации (сайт + docs + каталог)
│       │   └── hot_swap.py         ← Blue/Green переиндексация без остановки бота
│       └── retrieval/
│           └── search.py           ← Семантический поиск по запросу
│
└── tools/                  ← Утилиты для IT-отдела (запускаются из терминала)
    ├── indexer_ctl.py      ← Управление переиндексацией (старт, статус, расписание)
    ├── indexer_ctl.py      ← Управление переиндексацией (старт, статус, расписание)
    ├── preview_urls.py     ← Посмотреть что будет проиндексировано
    ├── inspect_db.py       ← Посмотреть содержимое базы по URL
    ├── debug_search.py     ← Проверить поиск по вопросу
    ├── reindex.py          ← Запустить переиндексацию напрямую (без API)
    ├── clear_index.py      ← Полностью очистить базу
    ├── export_chunks.py    ← Экспорт чанков в JSON для ручного редактирования
    ├── index_from_chunks.py← Индексация из отредактированного JSON
    ├── rebuild_catalog.py  ← Обновить только каталог-чанки (быстро)
    ├── chunk_editor.py     ← Браузерный редактор чанков (порт 8080)
    └── backup.py           ← Резервная копия базы данных
```

## Первый запуск (один раз)

### Требования

- Python 3.10+
- Docker Desktop (установлен и запущен)
- Аккаунт OpenAI с пополненным балансом
- Telegram Bot Token (от @BotFather)

### Шаг 1 — Установить зависимости Python

```bash
pip install -r requirements.txt
```

### Шаг 2 — Создать файлы конфигурации

Нужно создать **два** `.env` файла.

**Файл 1: `rag_service/.env`** (для сервиса поиска)

```bash
cp .env.example rag_service/.env
```

Открыть `rag_service/.env` и заполнить:

```ini
OPENAI_API_KEY=sk-proj-...         # Ключ OpenAI (platform.openai.com/api-keys)
API_SECRET_KEY=придумайте_ключ_16+ # Любой пароль для защиты API (минимум 16 символов)

QDRANT_HOST=localhost
QDRANT_PORT=6333
QDRANT_COLLECTION_NAME=caiu_knowledge_base

SITE_BASE_URL=https://caiu.edu.kz
SITEMAP_URL=https://caiu.edu.kz/sitemap.xml

# Необязательно — для подключения приватных Google Docs через сервисный аккаунт:
GOOGLE_SERVICE_ACCOUNT_FILE=service_account.json
GOOGLE_DOC_ID=             # ID одного документа (или оставьте пустым)
# Несколько документов добавляются в rag_service/app/config.py → GOOGLE_DOC_IDS
```

**Файл 2: `.env`** в корне проекта (для бота)

```bash
cp .env.example .env
```

Открыть `.env` и заполнить:

```ini
BOT_TOKEN=1234567890:AAF...        # Токен бота от @BotFather
OPENAI_API_KEY=sk-proj-...         # Тот же ключ OpenAI
RAG_SERVICE_URL=http://localhost:8001
RAG_API_KEY=придумайте_ключ_16+    # Тот же пароль что в API_SECRET_KEY выше
```

> **Важно:** `API_SECRET_KEY` в `rag_service/.env` и `RAG_API_KEY` в `.env` должны быть **одинаковыми**. Это пароль которым бот авторизуется в сервисе поиска.

### Шаг 3 — Запустить базу данных

```bash
cd rag_service
docker-compose up -d
```

Проверить что база запущена:
```bash
docker ps
# Должны видеть контейнер: qdrant/qdrant (статус Up)
```

### Шаг 4 — Первая индексация сайта (30–60 минут)

```bash
cd rag_service
python -m app.parser
```

Что происходит во время индексации:
1. Система скачивает sitemap с caiu.edu.kz и получает список всех страниц (~200 URL)
2. Каждая страница скачивается и очищается от HTML-разметки
3. Текст разбивается на фрагменты по ~200 слов с учётом заголовков разделов
4. Для каждого фрагмента OpenAI генерирует 4 возможных вопроса
5. Все фрагменты и вопросы сохраняются в Qdrant с их векторными представлениями

Стоимость первой индексации: **~$0.20–0.30** (списывается с баланса OpenAI).

Пример вывода:
```
[1/204] https://caiu.edu.kz/history-of-the-university-ru/
  -> Chunks: 4  |  Questions: 16  |  Saved: 20
[2/204] https://caiu.edu.kz/obshhezhitie/
  -> Chunks: 3  |  Questions: 12  |  Saved: 15
...
[Pipeline] Done! pages=198, chunks=412, questions=1648, total_qdrant=2060
```

### Шаг 5 — Проверить что всё работает

```bash
# В одном терминале:
cd rag_service && python run_api.py
# Должно появиться: Uvicorn running on http://0.0.0.0:8001

# В другом терминале:
curl http://localhost:8001/health
# Ответ: {"status": "ok", ...}
```

## Ежедневная работа

### Запуск

Открыть два терминала и запустить в каждом:

**Терминал 1 — сервис поиска:**
```bash
cd rag_service
python run_api.py
```

**Терминал 2 — бот:**
```bash
python bot/run.py
```

Оба процесса должны работать одновременно. Если один остановится — бот перестанет отвечать (или будет отвечать без поиска по базе, о чём укажет 🔴 индикатор).

### Остановка

В каждом терминале нажать `Ctrl+C`.

### Индикаторы в ответах бота

В конце каждого ответа бота есть маленький индикатор:

| Индикатор | Значение |
|---|---|
| 🟢 | Ответ основан на данных из базы знаний сайта |
| 🔴 | Сервис поиска недоступен, GPT отвечает без базы (менее точно) |

Если видите 🔴 — значит сервис поиска не запущен или упал.

## Обновление базы знаний

### Когда нужно обновлять?

- На сайте caiu.edu.kz добавились или изменились страницы
- Изменились правила приёма, стоимость обучения, список специальностей
- Добавили новый Google Doc в конфигурацию

### Горячая переиндексация (рекомендуется)

Этот способ **не останавливает бота** — абитуриенты продолжают получать ответы во время обновления.

```bash
python tools/indexer_ctl.py start
```

Система запустит переиндексацию в фоне. Бот работает со старыми данными до тех пор пока новые не будут готовы, затем переключится автоматически.

Следить за процессом:
```bash
python tools/indexer_ctl.py status
```

Пример вывода:
```
==================================================
СТАТУС ИНДЕКСАЦИИ
==================================================
В процессе:         да ⏳
Запущено:           2025-06-15T03:00:12+00:00
Активная коллекция: caiu_knowledge_base_blue
Записей в Qdrant:   2060
==================================================
```

После завершения:
```
==================================================
СТАТУС ИНДЕКСАЦИИ
==================================================
В процессе:         нет ✅
Активная коллекция: caiu_knowledge_base_green
Записей в Qdrant:   2087

📋 Последняя индексация:
   Статус:   completed
   Коллекция: caiu_knowledge_base_green (atomic)
   Страниц:  201 (пропущено: 12)
   Чанков:   428
   Вопросов: 1712
==================================================
```

### Запланировать переиндексацию заранее

Удобно настроить автоматическое обновление ночью, когда нагрузка минимальна:

```bash
# Сегодня/завтра в 03:00 ночи
python tools/indexer_ctl.py schedule "03:00"

# В конкретную дату
python tools/indexer_ctl.py schedule "15.06 03:00"

# С указанием года
python tools/indexer_ctl.py schedule "15.06.2025 03:00"
```

Посмотреть что запланировано:
```bash
python tools/indexer_ctl.py status
# В выводе будет: "📅 Запланировано: 15.06.2025 03:00"
```

Отменить расписание:
```bash
python tools/indexer_ctl.py unschedule
```

> **Важно:** чтобы расписание сработало, `rag_service` должен быть запущен (`python run_api.py`). Планировщик встроен в сервис.

## Добавить Google Docs в базу знаний

Если у вас есть информация которой нет на сайте (например, подробные правила приёма, FAQ, прейскурант) — её можно добавить через Google Docs.

Система работает с **приватными** документами через сервисный аккаунт Google Cloud.

---

### Шаг 1 — Подготовить сервисный аккаунт (один раз)

Если `service_account.json` уже есть в папке `rag_service/` — пропустите этот шаг.

1. Перейдите в [Google Cloud Console](https://console.cloud.google.com/)
2. Создайте проект (или выберите существующий)
3. Включите два API: **Google Drive API** и **Google Docs API**
   - Меню → APIs & Services → Library → найдите каждый → Enable
4. Создайте сервисный аккаунт:
   - APIs & Services → Credentials → Create Credentials → Service Account
   - Дайте любое имя, нажмите Done
5. Скачайте JSON-ключ:
   - Кликните на созданный аккаунт → вкладка Keys → Add Key → JSON
   - Скачанный файл переименуйте в `service_account.json` и положите в `rag_service/`
6. Запомните email сервисного аккаунта — он выглядит так:
   ```
   my-bot@my-project.iam.gserviceaccount.com
   ```

---

### Шаг 2 — Дать доступ к документу

Откройте нужный Google Doc. Нажмите **"Поделиться"** и добавьте email сервисного аккаунта с правом **"Читатель"**:

```
my-bot@my-project.iam.gserviceaccount.com
```

> Документ остаётся приватным. Доступ есть только у сервисного аккаунта.

---

### Шаг 3 — Получить ID документа

В адресной строке браузера:
```
https://docs.google.com/document/d/1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms/edit
                                   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                   Это и есть ID документа
```

---

### Шаг 4 — Добавить в конфигурацию

Откройте `rag_service/.env` и укажите путь к ключу и ID документа:

```ini
GOOGLE_SERVICE_ACCOUNT_FILE=service_account.json
GOOGLE_DOC_ID=1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms
```

Если нужно добавить **несколько документов** — откройте `rag_service/app/config.py` и заполните список `GOOGLE_DOC_IDS`:

```python
GOOGLE_DOC_IDS = [
    {"id": "1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms", "title": "Правила приёма 2025"},
    {"id": "2CyiNWt1YSB6...", "title": "Стоимость обучения 2025"},
]
```

> Поле `"title"` — название документа как оно будет упоминаться в ответах бота.
> Если оставить пустым, система возьмёт первую строку документа.
>
> `GOOGLE_DOC_ID` в `.env` и `GOOGLE_DOC_IDS` в `config.py` работают вместе — оба списка объединяются при индексации.

```bash
python tools/indexer_ctl.py start
```

### Как правильно оформить Google Doc для хорошего поиска

Качество поиска напрямую зависит от того, как структурирован документ. Система разбивает документ на фрагменты по заголовкам — каждый раздел становится отдельным фрагментом с понятным контекстом.

**Используйте стили заголовков, а не просто жирный текст**

В Google Docs есть выпадающий список стилей абзаца (по умолчанию показывает "Обычный текст"). Заголовки нужно оформлять именно через него:

```
Заголовок 1  ← крупные разделы (Условия поступления, Стоимость обучения)
Заголовок 2  ← подразделы (Документы для поступления, Гранты)
Заголовок 3  ← мелкие подпункты (при необходимости)
```

Жирный текст (`**Ctrl+B**`) **не является заголовком** — система его не распознает как границу раздела.

**Пример хорошо структурированного документа:**

```
[Заголовок 1] Правила приёма в ЦАИУ 2025

[Обычный текст] Документ содержит актуальные правила поступления
на 2025-2026 учебный год.

[Заголовок 2] Необходимые документы

[Обычный текст] Для поступления на бакалавриат необходимо предоставить:
- Аттестат об окончании школы (оригинал)
- Удостоверение личности (копия)
- Сертификат ЕНТ
- 6 фотографий 3×4

[Заголовок 2] Стоимость обучения

[Обычный текст] Годовая стоимость контрактного обучения:
- Технические специальности: 450 000 тг
- Гуманитарные специальности: 380 000 тг

[Заголовок 2] Гранты и скидки

[Обычный текст] Университет предоставляет скидки отличникам...
```

**Что происходит при индексации:**

Каждый раздел между заголовками станет отдельным фрагментом в базе:
```
[Правила приёма 2025 > Необходимые документы]
Для поступления на бакалавриат необходимо предоставить:
- Аттестат...

[Правила приёма 2025 > Стоимость обучения]
Годовая стоимость контрактного обучения:
- Технические специальности: 450 000 тг...
```

Когда абитуриент спросит "сколько стоит обучение?" — система найдёт именно второй фрагмент, а не весь документ целиком.

**Рекомендации по содержанию:**

- Пишите конкретные цифры, даты, суммы — они важнее общих описаний
- Каждый раздел должен отвечать на один конкретный вопрос
- Не дублируйте информацию которая уже есть на сайте caiu.edu.kz
- Оптимальный объём раздела: 100–300 слов

## Управление расписанием переиндексации

Все команды управления запускаются из терминала через `tools/indexer_ctl.py`.

**Требование:** `rag_service` должен быть запущен (`python rag_service/run_api.py`).

| Команда | Описание |
|---|---|
| `python tools/indexer_ctl.py start` | Немедленно запустить переиндексацию в фоне |
| `python tools/indexer_ctl.py status` | Показать статус: идёт ли индексация, расписание, последний результат |
| `python tools/indexer_ctl.py schedule "03:00"` | Запланировать на сегодня/завтра в 03:00 |
| `python tools/indexer_ctl.py schedule "15.06 03:00"` | Запланировать на 15 июня в 03:00 |
| `python tools/indexer_ctl.py schedule "15.06.2025 03:00"` | То же с годом |
| `python tools/indexer_ctl.py unschedule` | Отменить запланированную переиндексацию |

> **Что будет если запустить переиндексацию пока уже идёт другая?**
> Второй запрос получит ошибку: `⚠️ Индексация уже идёт`. Двойного запуска не произойдёт.

> **Что будет если переиндексация прервётся на середине?**
> База знаний **не пострадает** — новые данные пишутся в резервную коллекцию. Если процесс прервётся, активная коллекция (которую использует бот) останется нетронутой. При следующем запуске индексация начнётся заново с нуля.

## Диагностика и отладка

### Предпросмотр: что будет проиндексировано

Перед запуском индексации можно посмотреть что именно попадёт в базу:

```bash
# Список всех URL
python tools/preview_urls.py

# Конкретный URL с подробностями
python tools/preview_urls.py https://caiu.edu.kz/history-of-the-university-ru/
```

Статусы URL:
- `[НОВЫЙ]` — страница будет проиндексирована впервые
- `[В БАЗЕ]` — уже есть, не изменилась → пропустится
- `[ИСКЛЮЧЁН]` — фильтр блокирует (новости, страницы на казахском `/kz/` и т.д.)

### Просмотр содержимого базы

Посмотреть все проиндексированные страницы:
```bash
python tools/inspect_db.py
```

Посмотреть фрагменты конкретной страницы:
```bash
python tools/inspect_db.py https://caiu.edu.kz/history-of-the-university-ru/
```

Только текстовые фрагменты без вопросов:
```bash
python tools/inspect_db.py https://caiu.edu.kz/history-of-the-university-ru/ --no-questions
```

Это полезно чтобы понять **почему бот не знает о чём-то**: можно увидеть как именно разбита страница, какие фрагменты попали в базу и есть ли там нужная информация.

### Тест поиска по конкретному вопросу

```bash
python tools/debug_search.py "сколько корпусов у университета"
```

Показывает:
- Какие фрагменты нашла система
- Рейтинг релевантности (score) каждого фрагмента
- Текст найденных фрагментов

Если нужная информация на сайте есть, но поиск её не находит — значит нужно переиндексировать или проверить текст фрагментов через `inspect_db.py`.

### Проверка состояния сервисов

```bash
# RAG-сервис
curl http://localhost:8001/health

# Статистика базы знаний
curl http://localhost:8001/stats

# База данных Qdrant (веб-интерфейс)
# Открыть в браузере: http://localhost:6333/dashboard
```

### Очистить базу и начать с нуля

Нужно если изменились настройки индексации (например, размер фрагментов):

```bash
python tools/clear_index.py
# После очистки:
cd rag_service && python -m app.parser
```

## Частые вопросы и проблемы

**Бот отвечает с индикатором 🔴**

Сервис поиска не запущен или упал. Запустите:
```bash
cd rag_service && python run_api.py
```

**Ошибка "Connection refused" при запуске сервиса**

База данных Qdrant не запущена. Выполните:
```bash
cd rag_service && docker-compose up -d
```

**Бот не знает о конкретной теме / даёт устаревшую информацию**

Информация на сайте обновилась, но база знаний не обновлялась. Запустите переиндексацию:
```bash
python tools/indexer_ctl.py start
```

**Поиск находит нерелевантные фрагменты**

Проверьте через `debug_search.py` что именно находит система. Если нужная страница есть в базе (проверьте через `inspect_db.py`) но поиск её не находит — попробуйте переиндексацию с очисткой:
```bash
python tools/clear_index.py
cd rag_service && python -m app.parser
```

**Нужно добавить информацию которой нет на сайте**

Создайте Google Doc, расшарьте его на email сервисного аккаунта, добавьте ID в `config.py`, переиндексируйте. Подробнее: раздел [Добавить Google Docs](#добавить-google-docs-в-базу-знаний).

**Сколько стоит работа бота?**

- Каждый вопрос пользователя: ~$0.001–0.003
- 10 000 вопросов в месяц: ~$10–30
- Полная переиндексация сайта: ~$0.20–0.30 (один раз)

**Можно ли запустить без интернета?**

Нет. Система требует интернет для:
- Обращений к OpenAI API (поиск и генерация ответов)
- Скачивания страниц сайта (только при индексации)

База данных Qdrant работает локально.

## Технические параметры

| Параметр | Значение | Описание |
|---|---|---|
| Размер фрагмента | 200 слов | Максимальный размер одного чанка |
| Перекрытие | 30 слов | Сколько слов повторяется между соседними чанками для сохранения контекста |
| Вопросов на фрагмент | 4 | GPT генерирует вопросы для улучшения поиска |
| Порог релевантности | 0.28 | Ниже этого значения → "нет информации" |
| Контекст для GPT | топ 5 фрагментов | Сколько фрагментов отдаётся в ChatGPT для формулировки ответа |
| Модель эмбеддингов | text-embedding-3-small | OpenAI, 1536 измерений |
| Модель ответов | gpt-4.1-mini | OpenAI |
| Порт сервиса поиска | 8001 | FastAPI |
| Порт базы данных | 6333 | Qdrant |
